# 评分规则与校准方法

本文件是工具包的方法论核心。**规则文本可以抄，锚点必须自己校准。**

## 一、为什么不能只写规则

LLM 打分的稳定性主要来自 **few-shot 锚点**，而不是规则文本的长度。同一个分数档，模型在没见过实例时倾向于保守或趋中；给 1-2 个真实确认过的样例，标尺立刻收窄。经验：

- 规则文本的边际收益递减很快，写到一定程度后，继续加细则会导致**规则互相冲突**（模型自己仲裁）和**规则律师化**（抠字面而不读语境）
- 正确的投入方向是**增加锚点覆盖**，让 1-5 每一档都有实例

## 二、锚点设计

**数量**：4-6 个，覆盖 1-5 全量程。关键是**低分端也要有锚点**——否则模型不敢打 1-2 分，全量分布会整体上浮。

**优先级**（按对分布的稳定作用排序）：

1. 众数档（通常是 2 分或 3 分）——决定整体标尺位置，最重要
2. 相邻档边界（2/3 边界、3/4 边界）——决定升档依据
3. 极值档（1 分、5 分）——决定量程端点

**写法**：每个锚点写「日期（当天发生了什么）= 分数档」，事件描述要具体到可复现判断，不要写抽象评价。例如：

> 锚点（2 分档）：合作剪辑视频、聊趣事、互相打趣，全天无情绪事件 = 2 分。**不因互动量大而升档。**

括号里同时要写明**边界规则**（什么情况不算升档），这比只写正例有效。

## 三、校准流程（推荐照做）

### 第 1 步：定位候选日

用关键词/统计从数据里挑，不要随机抽（随机抽命中特殊日的概率低）：

```python
# 低分端候选：消息量 10-40 条、总字数 <400、无亲昵词
# 高分端候选（负面）：冲突词 —— 我错了/原谅/生气/冷战/不想理
# 高分端候选（正面）：出行词 —— 见面/车站/高铁/接你/出站
# 中间档：消息量中位数附近、内容平淡的普通日
```

### 第 2 步：给当事人看，逐个定分

把候选日的**精简对话**（抽样展示，不用全量）给当事人，让他凭记忆定分。**不要自己定分**——他才是标尺的所有者，尤其"这天算吵架吗"这类判断只有当事人知道。

### 第 3 步：放入 prompt，复跑已知日验证

把定下的锚点写进 `prompt_template.py`，然后：

1. 跑**已确认过的日子**（校准集），检查分数是否落位
2. 同时跑几个**普通日子**，检查是否全挤在 3-4 分（这是最常见的失败模式）

### 第 4 步：看全量分布是否合理

全量跑完后做分布体检：

- 各档是否都有分布（1-5 都要有）
- 众数档是否落在你预期的位置
- 极值档占比是否离谱（例如 5 分占了 30%，说明标尺太松）

分布明显异常时，回头补锚点，**整段重跑**（别局部修补，会造成标准不一致）。

## 四、实测校准案例（结构示范）

一次真实项目的校准过程：

| 轮次 | 动作 | 结果 |
|------|------|------|
| 第 1 轮 | 单锚点（2-3 边界）试跑 3 天 | 锚定日偏松（该 2 打 3），极性字段全标"混合"失去区分度 |
| 修正 | 极性规则收紧为"仅双方都强且拉扯才标混合" | 10 天里 9 天回归主导方向 |
| 第 2 轮 | 补 2 分档、3 分档锚点后复跑 | 已确认日全部落位 |
| 第 3 轮 | 补 1 分档、5 分正、5 分负锚点 | 量程端点收口，复跑稳定 |
| 全量 | 1200 天 | 分布：1 分 29 天 / 2 分 185 / 3 分 694 / 4 分 246 / 5 分 46，符合预期 |

关键经验：

- **偏好字段（极性）比分数更容易失效**。如果某个分类字段 90% 都是同一个值（例如全是"混合"），说明定义太宽松，等于没这个字段
- **锚定日的判断需要完整信息**。第一次抽样展示时不完整的描述会导致当事人给出错误基准（漏看了晚间内容），回到数据核对后修正
- **反面案例同样有价值**。当事人确认"这天只有 2 分"时，要写清"为什么不升档"，否则模型会自己找理由升档

## 五、防漂移

1. **冻结 prompt**：规则文本写在 `prompt_template.py` 一处，所有 worker 共用，不得在调用处拼接
2. **temperature=0、关闭思考模式**：压随机性，保证同一输入同一输出
3. **抽检**：全量跑完后随机抽 5%（例如 60 天）重跑一遍，与首次结果对比；偏差超过 1 分的时段整段重跑
4. **窗口数不影响标准**：并发数只影响速度，不影响结果——只要 prompt 与参数冻结，5 并发的输出与单并发的输出一致

## 六、什么时候需要重校准

- 换了数据集（不同情侣/不同时期）
- 当事人指出某天分数明显不对，且不是孤例
- 全量分布明显异常
- 改了规则文本的任何一处

## 七、实测稳定性数据（跨环境复现实验）

一次真实项目的对照实验，用于量化"改了什么会导致多大偏差"：

| 对比 | 样本 | 完全一致 | 平均绝对偏差 | 相差 >=2 分 | 极性一致 |
|------|------|---------|-------------|------------|---------|
| 同一 prompt、同一环境重跑 | 60 天 | 93.3% | 0.067 | 0 天 | 98.3% |
| 同一 prompt、跨环境（另一台/另一窗口）复跑 | 60 天 | 100.0% | 0.000 | 0 天 | 98.3% |
| **不同 prompt 版本**（泛化锚点 vs 真实锚点） | 1200 天 | 84.9% | 0.151 | 0 天 | 93.6% |

结论：

1. **模型层面的噪声很小**（同 prompt 重跑 93-100% 一致，偏差 <=0.07 分），且方向无偏
2. **prompt 版本差异是主要偏差来源**，且是**系统性单边偏移**（该例中偏向更保守，150 天降分 vs 31 天升分）
3. 偏差集中在 **2/3 分边界**（该例 111/1200 天由 3 降 2），高端（4-5 分）交集率 85.4%，最弱维度是"是否含大事件"（交集率 72.6%）
4. 年度均值差仅 0.06-0.15，**趋势类结论不受影响**；但**计数类统计（如每年冲突次数）必须锁定同一 prompt 版本**

实操建议：把每个数据集的校准版 prompt 存成独立文件（如 `prompt_calibrated.txt`），以 `--prompt-file` 加载；改 prompt 前后都要用已知答案的日子验证，且**不要在同一个统计里混用两版结果**。
