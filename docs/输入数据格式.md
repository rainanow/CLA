# 输入数据格式

## 1. 支持的输入

一份 SQLite 数据库文件，含一张消息表，默认表名 `msg`。

## 2. 字段规范

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `ts` | INTEGER | 是 | **毫秒**时间戳。常见坑：秒级时间戳会导致日期计算全错 |
| `tstr` | TEXT | 是 | `YYYY-MM-DD HH:MM:SS`，管线按前 10 位切天、第 12-16 位取时间 |
| `sender` | TEXT | 是 | 发送者昵称。约定用 `'0'` 表示系统/未知，管线会剔除 |
| `mtype` | TEXT | 是 | 消息类型。`type_1` 普通消息；`type_3` 回复；`type_6` 语音；`type_9` 视频；`type_17` 表情；`type_19` 空消息（剔除） |
| `text` | TEXT | 是 | 消息正文。资源消息为占位符：`[图片: hash.png]`、`[视频: /path/x.mp4]`、`[文件: name]`、`[语音]` |
| `system` | INTEGER | 是 | 1 = 系统消息，剔除 |
| `hasres` | INTEGER | 否 | 是否含资源 |
| `restype` | TEXT | 否 | `image` / `audio` / `video` / `file` |

## 3. 换数据源时怎么做

**不要改清洗逻辑，改映射。** 如果你的导出工具字段名不同，写一个一次性转换脚本，把数据灌进上面这张 `msg` 表即可。示例：

```python
import sqlite3
src = sqlite3.connect('other_export.db')
dst = sqlite3.connect('chat.db')
dst.execute('''CREATE TABLE msg (
  id TEXT, seq INTEGER, ts INTEGER, tstr TEXT, sender TEXT,
  mtype TEXT, text TEXT, recalled INTEGER, system INTEGER,
  hasres INTEGER, restype TEXT)''')
for row in src.execute('SELECT create_time, user, content FROM messages'):
```

## 4. 数据特征对分析的影响（务必让使用方知晓）

- **图片/语音/视频内容不可见**，只有占位符。模型无法知晓图片里是什么，prompt 中必须声明这个盲区，否则模型会编造图片内容。
- **系统消息与自动回复**是机器生成的，必须剔除。`[自动回复]` 前缀在清洗阶段处理。
- **刷屏连发**（同一人连续发相同文本 >=5 条）会在清洗阶段折叠为 `文本 xN`，避免虚增情绪强度。
- **无聊天日**：日历上约 20% 的日期没有记录，这些天不评分（在可视化里显示为灰色），不要用 1 分或 0 分填补——语义不同。
